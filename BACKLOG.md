# Prism — роадмап к публичному web-релизу

> **Как вести этот файл (читать первым после компакта; карта репо — `ARCHITECTURE.md`).**
> Единственный источник правды по «куда идём, что делаем и что решили». Правила:
> (1) **самодостаточность** — никаких ссылок на чат/память; (2) активная работа — в
> майлстоунах явными чекбокс-задачами с критерием готовности; (3) каждое принятое
> дизайн-решение — в «Журнал решений» одной строкой; (4) **выполненное и устаревшее
> УДАЛЯЕМ**, а не помечаем «сделано» — история живёт в git; (5) **роадмап — карта,
> не клетка**: спонтанная хотелка пользователя всегда приоритетнее очередного пункта
> майлстоуна — вклиниваем сразу, майлстоуны сдвигаются, отклонение фиксируем строкой
> в журнале. Роадмап отвечает на «что дальше, когда нет явной хотелки» и охраняет
> одно: фундамент M1 не размывать — он окупает всё остальное.

## Цель

**Публичная web-версия Prism**: браузерный клиент (Godot HTML5), VPS, аккаунты,
матчмейкинг, полные сеты 5 цветов, колодостроитель, AI-противник, режимы
(драфт/арена), прогрессия (ранги/титулы). **Все карты доступны всем по умолчанию**
(нет коллекции/анлока карт → ноль pay-to-win); экономика — **только косметика**
(рамки/борды/скины героев) за мягкую валюту, с тирами редкости и колесом/лутбоксами.

**Состояние на старте роадмапа (2026-06):** играбельный e2e-стек — C++-движок
(82 теста, грамматика эффектов, 22 ключевика, 4 пассивки героев), WebSocket-сервер
приватных комнат (код+пароль), Godot-клиент (координатор + модули, 40 headless-тестов,
CI). 69 карт, 4 героя. Рефакторинг клиента завершён (Main 1661→836, слой `Rules`,
сигналы-намерения). Чего НЕТ: сериализации состояния, перечисления легальных ходов,
реконнекта, бота, настоящих колод (играет `demoDeck` — по 1 копии всего сета),
колодостроителя, аккаунтов/персистентности, web-экспорта, TLS, адаптивного UI,
звука (вообще), EN-имён, косметики/экономики.

## Целевая архитектура

```
[Браузер: Godot HTML5]──┐
[Десктоп: Godot]────────┤ wss (JSON, versioned)
                        ▼
        [reverse-proxy: caddy — TLS, COOP/COEP, статика клиента]
                        ▼
        [prism_server (C++, один процесс)]
          ├─ лобби: приватные комнаты + открытая очередь матчмейкинга
          ├─ Game-движок (авторитарный; редактированные view)
          ├─ Bot (в процессе, занимает второе кресло)
          ├─ сериализация партий → реконнект, реплеи (seed+лог действий)
          └─ мета-слой → [SQLite]: аккаунты(токены), колоды, прогрессия,
                          инвентарь КОСМЕТИКИ (карты не коллекционируются), история
```

Принципы: **один сервер-процесс** (не плодим сервисы — SQLite, бот и мета живут
внутри `prism_server`); **сервер никому не верит** (валидация колод и действий);
**движок детерминирован** (seed + лог действий = реплей); клиент — тонкий рендер
view (это уже так — сохранять).

## Архитектурные решения на будущее (зафиксировано, чтобы не переделывать)

1. **Сначала фундамент движка, потом контент.** Перечисление легальных действий и
   сериализация состояния разблокируют сразу: бота, реконнект, фаззинг, реплеи,
   админ-панель. Делать ДО контент-рывка.
2. **Реплей = seed + лог действий.** Движок детерминирован (`Game(lib, deck0, deck1,
   seed)`); полная сериализация нужна только для реконнекта/админки, реплеи дешевле.
3. **Карты НЕ имеют редкости и НЕ коллекционируются** — все доступны всем по
   умолчанию (ноль pay-to-win; проще бэкенд — нет коллекции на аккаунт). Редкость
   живёт на КОСМЕТИКЕ (рамки/борды/скины), это отдельный тип данных, `CardDef` не
   трогает. `name.en` — конвенция контент-трека (добавляем к каждой карте по мере
   написания, чтобы не бэкфиллить; локализация — пост-релиз).
4. **Версия протокола.** Поле `v` в первом сообщении клиента — ДО появления
   публичных клиентов (старые браузерные клиенты живут в кэшах).
5. **Колоды валидирует сервер** (30 карт, ≤2 копии, существующие id) — `readLoadout`
   сейчас принимает что угодно; это чит-вектор. Правило одно, живёт в движке/сервере.
6. **Бот — в процессе сервера**, не отдельный клиент: садится на seat 1 комнаты
   «vs AI». Интерфейс бота = перечисление легальных действий + оценка.
7. **Web-экспорт**: wss обязателен (https-страница не может ws://), за caddy;
   threads-экспорт Godot требует заголовков COOP/COEP — caddy их отдаёт.
8. **Экономика — только мягкая валюта** (никаких реальных денег в лутбоксах без
   отдельного юр-анализа); честность дропа (pity) фиксируется в дизайне сразу.
9. **Звук обязателен до публики** (сейчас 0 аудио): SFX на события + эмбиент.
10. Godot 4 остаётся; позиционной боёвки нет (решено ранее).

## Майлстоуны (последовательные)

Размеры: S — день-два сессий, M — несколько, L — много, XL — фоновый поток.

### M1 — Фундамент движка (L) ✓ закрыт
legalActions / сериализация / реплеи / фазз / лог действий в комнате (`Room` пишет
принятые действия → `makeReplay`, дамп в `replays/` на game-over; тот же лог питает
реконнект M5). ctest зелёный с фаззом, реплей бит-в-бит.

### M2 — Дев-ускорители (M)
Зачем: резко удешевляет проверку контента и багов (сейчас сценарий = сыграть партию).
- [ ] Админ-панель (dev-сборка): `debug/setState` на сервере (принимает
      `Game::fromJson`) + клиентский редактор сценария (борд/рука/мана/hp/ход).
- [ ] Лог действий в UI (лента «что произошло»): сервер шлёт событие-сообщения
      рядом с view (или клиентский дифф) — видно эффекты соперника и цепочки.
- [ ] Реплей-просмотр в клиенте (минимально: прокрутка действий по логу из M1).
Критерий: любой игровой сценарий воспроизводится за <1 минуты без живой партии.

### M3 — Бот и баланс-пайплайн (L)
Зачем: одиночный режим + автоматическая проверка баланса для контент-рывка.
- [ ] Бот v1: эвристика поверх `legalActions()` (жадная оценка: темп/размен/урон в
      лицо/кривая маны). Без поиска; играет «прилично», не идеально.
- [ ] Кнопка «Игра с ботом» в клиенте (комната с ботом на seat 1).
- [ ] Self-play CLI: N партий бот-vs-бот → отчёт (winrate по цветам/героям/картам,
      средняя длина партии). Связка с `tools/balance.py`.
- [ ] (после v1) Бот v2 — лёгкий поиск (1-ply с симуляцией размена) — по желанию.
Критерий: бот доигрывает любую партию без зависаний; self-play на 1000 партий
выдаёт отчёт; в клиенте можно играть одному.

### M4 — Колодостроитель + валидация колод (M)
- [ ] Экран конструктора: сетка ВСЕХ карт (все доступны — нет коллекции; фильтры
      цвет/тип/стоимость/ключевик), сборка 30/≤2 с живой валидацией и кривой маны.
- [ ] Серверная валидация колод: 30 карт, ≤2 копии, валидные id, не-hero; отказ →
      `joinError`. Единое правило в движке/сервере. (Перенесено из M1 — валидацию
      делаем вместе с билдером, иначе негде взять легальную колоду.)
- [ ] Decks: пресеты-архетипы (моно-цвета + 2-3 сплава) — играбельны без билдера.
- [ ] Дев-песочница: текущая «1 копия каждой карты» остаётся как dev-only
      (валидация байпасится) для теста всего сета; `demoDeck` живёт до этого этапа.
- [ ] Локальное хранение колод (`user://decks.cfg`, формат как `Decks`), выбор в лобби.
Критерий: собрал колоду → сохранил → сыграл ей с другом и с ботом; кривая/мусор
от чужого клиента отбиваются.

### M5 — Web-готовность и деплой (L)
Цель этапа — **десктоп-браузеры** (мышь); мобилки/тач — отдельный пост-релизный этап.
- [x] Godot web-экспорт (HTML5): собран, ~180МБ, однопоточный → COOP/COEP не нужны;
      пресет `Web` закоммичен. Клиент сам коннектится к same-origin `wss://host/ws`.
- [x] **Turnkey-деплой готов и проверен локально** (`deploy/`): один параметризованный
      `Caddyfile` (TLS+статика+wss-прокси) обслуживает оба пути —
      **Docker Compose** (`Dockerfile` собирает сервер, `docker-compose.yml`:
      prism+caddy, клиент монтируется томом, образ сервера 78МБ) и **bare systemd**
      (`prism-server.service`). Полный стек прогнан в контейнерах: caddy отдаёт
      клиент + `/ws`→сервер, матч идёт. `deploy/local_serve.py` — прод-зеркало без VM.
- [ ] **Завести VM + хостнейм (действие пользователя):** Oracle Always Free
      (10ТБ egress) или дешёвая VPS (~$4–6/мес) + DuckDNS/домен (A-запись на IP).
      Затем по `deploy/README.md` §2A: `docker compose up -d --build`. Заодно
      проверить коллизии имени «Prism» (игры/трейдмарки) — возможен ребренд витрины.
- [ ] Харднинг сервера: idle-таймауты сокетов, GC пустых комнат, rate-limit
      сообщений, лимит комнат на IP. (Лимит кадра 1 MiB уже есть в `ws.hpp`.)
      Текущее состояние ок для приватных комнат: брошенная комната чистится при
      обрыве хоста (POLLHUP→dropClient), одна комната на сокет.
- [ ] Реконнект: токен места (room+seat+secret), при обрыве клиент переподключается
      и получает текущий view (сериализация из M1); таймер дисконнекта → техлуз.
- [ ] Поле `v` протокола + отказ несовместимым клиентам.
Критерий: друг открывает URL в браузере и играет; обрыв сети не убивает матч.

### M6 — Мета-сервер: аккаунты и матчмейкинг (L)
- [ ] SQLite в `prism_server`: players (токен-аккаунты, ник), decks, cosmetics
      (инвентарь), match_history. **Карты не коллекционируются** — таблицы коллекции
      нет, все карты у всех. Миграции — простые versioned-скрипты.
- [ ] Лёгкие аккаунты: анонимный токен при первом входе (хранится клиентом),
      ник; почта/пароль — позже, при необходимости.
- [ ] Открытая очередь «Быстрая игра» рядом с приватными комнатами.
- [ ] Колоды переезжают с клиента на сервер (клиентский кэш остаётся).
Критерий: два незнакомых игрока находят друг друга кнопкой; колоды живут в аккаунте.

### M7 — Режимы и прогрессия (L)
- [ ] Драфт/арена: серверная раздача пиков (пулы — по цвету/стоимости, редкости у
      карт нет), драфт-колода живёт в аккаунте до конца забега; счёт побед.
- [ ] Ранги: ладдер по сезонам, высший ранг = титул «Испытание Мастерства».
- [ ] Базовые квесты/дейлики (опционально, питает экономику M8).
Критерий: полный забег арены и видимый ранг в профиле.

### M8 — Экономика и кастомизация (XL, дизайн-тяжёлый)
**Только косметика — геймплей (карты) весь бесплатен → ноль pay-to-win.**
- [ ] Мягкая валюта из побед/квестов; косметика покупается/открывается за неё.
- [ ] «Лудоманские» ивенты: колесо фортуны, лутбоксы — с честным pity, дроп —
      **только косметика** (рамки/борды/скины/эффекты), с тирами редкости.
- [ ] Скины: рамки карт, борды, альтернативные арты героев (пайплайн MJ есть).
Критерий: новый аккаунт проходит путь «играю → зарабатываю → открываю косметику»;
никакой контент-стены, все карты доступны с первого матча.

## Параллельный трек К — контент (XL, фоновый)

Полные сеты: цель **~125–150 карт** (25–30 на цвет с двуцветками), **герой(и) на
каждый цветовой архетип** (сейчас 4; цель 6+). Правила трека:
- Батчи по 10–15 карт; каждый батч: дизайн → `name.en`/арт-промпты
  (`tools/build_prompts.py`) → `balance.py` → **после M3** self-play отчёт → правки.
- Равенство типов сета (см. Журнал решений) держим в каждом батче.
- Новые ключевики — по кукбуку `ARCHITECTURE.md A7`; кандидаты на возврат — см.
  «Вырезанные ключевики»; `ambush`/`refract` требуют триггеров вне своего хода
  (механика для отдельного захода).
- До M3 батчи маленькие и осторожные (баланс вручную), после M3 — конвейер.

  отдельный пост-релизный этап (тач-управление переосмысляется: сейчас драг+дабл-тап);
  (2) **язык релиза — RU**, EN-локализация (генератор правил + UI) — после релиза,
  `name.en` копим в данных с контент-батчей; (3) **экономика — только игровая
  валюта**, реальных денег нет → аккаунты остаются лёгкими (токен), платёжной
  инфры и юр-рисков лутбоксов нет; (4) **VPS/домена пока нет** — подбор (бюджет
  turnkey-деплой (`deploy/`, Docker+caddy) готов и проверен локально; остаётся
      завести VM (Oracle Always Free / дешёвая VPS) + хостнейм — действие пользователя.
- **Баланс сета (сетка, чтобы тюнить от единой базы).** Ванильная стат-линия
  существа: `ATK+HP ≈ 2·T + 1`, где `T` = полная стоимость. Ключевики выкупаются
  из этих очков (≈: pierce/ward/regen/self_lifesteal/growth ≈ 1.5; shield/bypass/
  photosynthesis ≈ 2; provoke/lingering/stealth/haunt/compost ≈ 1; split/germinate/
  decoy ≈ 1.5). Цветные пипы — лёгкая компенсация (~+1). Кривая T1–T8, бугор T3–4;
  провок-стены — высокий HP/низкий ATK; фотосинтез — временная мана; `damage_all`
  бьёт и свою доску. Пятицветки — аспирационный верх. Скорер: `tools/balance.py`.
- **Резонанс — снапшот при выходе** (не непрерывный), иначе снежный ком в лейте.
- **Силы героев — пассивные, не кнопки**: постоянная черта малой магнитуды; герой =
  `CardDef type:hero`, не в колоде; once-per-turn — счётчик `heroPowerUses`. Урон
  герою — всплывающая `-N` у медальона.
- **4 героя (≈равной силы):** Ирида «Призма»/`spectral_shift`; Эреб «Затмение»/
  `lighteater`; Тициана «Палитра»/`palette`; Гемма «Огранка»/`facet`. Единый стиль
  «живого света» (Эреб — ч/б). Кандидат на возрождение: Кьяра «Линза» (`hero_lens.png`
  сохранён). Детали — `ART_HEROES.md`.
- **Схема стола — «фланговые медальоны»**: герой слева, стол в центре, стопки справа.
- **Арты: герои 1:1 (1024²), карты 2:3.** Стиль — «существа из живого света»
  (`ART.md`); **имя и арт изображают один субъект**.
- **Жесты:** драг = разыграть/атаковать, **двойной тап = в ману**; цель — только
  перетаскиванием (клик-таргетинг вырезан).
- **Лицо карты:** арт во весь кадр + ободок + статусы; имя/правила — в тултипе.
- **Временная мана видна** (пипсы по `max(crystals, available)`); выбор цвета
  банкуемой мультицветки — радиальный пикер; выбор кристаллов на generic-часть —
  тап-пикер (`ManaSpendPicker`), движок принимает `genericPay`.
- **Freeze vs Blind:** заморозка — не атакует, но отвечает; ослепление — не наносит
  боевой урон вообще.
- **Морок (haunt):** иллюзия-токен наследует боевые ключевики, но не перерождается
  и не сыплет споры (`token` гейтит триггеры).
- **Сброс — пока информационный** (только размер наружу); задел под реанимацию.
- **DEF убрали:** ATK/HP, взаимный боевой урон (как HS).
- **Равенство типов сета:** моно поровну (3/цвет), двуцветки поровну (1/пара),
  нейтраль (5) и пятицветки (5, префикс `prismatic_`) — отдельные пулы.
- **Scry не меняет счётчик колоды** (peek-карты числятся в колоде).
- Позиционная боёвка — **НЕ делаем**.

## Открытые вопросы / идеи

- **Ось различия — ГЕРОЙ, а не колода** (кандидат): общая/пресетная колода, глубина
  в герое с китом способностей. Не реализуем — смена идентичности игры; вернуться
  при дизайне M7-режимов.
- **Архетип «бей по своим»** — движок готов (селекторы friendly/any); чистый контент.
- **«Мана — контестед-ресурс»** — нужны ключевики атаки по мане/перекраски; отложено.
- **Плагины (как HS Deck Tracker):** read-only API состояния матча + песочница;
  после M6 (нужны стабильный протокол и аккаунты).
- **Lua-«аварийный люк»** (sol2) для экзотики, если грамматики не хватит.
