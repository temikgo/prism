# Prism — рефакторинг клиента (Godot): целевая архитектура и остаток

> Что уже сделано (модуляризация `Main.gd` на 9+ модулей; инкрементальный борд P1–P4) —
> зафиксировано в истории git и в карте модулей `ARCHITECTURE.md` (раздел A4). Здесь —
> только **живое**: целевая форма `Main`, почему дальнейшее дробление ждёт архзадачи и
> оставшийся план. Поведение при рефакторинге не меняем (чистые переносы, проверка
> `Shot.gd`/`ShotMenu.gd` + live-прогон, отдельный коммит, не коммитим до проверки).

## 1. Целевая архитектура

```
Main (координатор, ~150–250 строк)
 ├─ Net            — WebSocket: connect/poll/send/recv → сигналы
 ├─ GameState      — хранит view; диффит входящие → damaged/died/summoned
 ├─ BoardView      — строит дерево из данных; emit-ит намерения (attack/play/place_mana/awaken)
 │    ├─ CardView (UiCard+лицо+тултип+статусы)   ├─ HeroMedallion   ├─ PilesColumn
 │    ├─ ManaRow/AwakenChip                       ├─ BoardRow        ├─ HandRow
 │    └─ overlays: Mulligan / Scry / GameOver / ManaPicker
 ├─ Fx             — lunge/shake/pop-in/float-numbers/motes (+ FxLayer)
 └─ модули-данные (без зависимостей от UI):
      CardData     — lookup/cost/name/keywords/target-side/affordability (чистые функции)
      Tokens/Theme — дизайн-токены + фабрики (gem/chip/label/style/art) — единая точка
```

Принцип: **данные вниз, сигналы вверх.** View-узлы принимают plain-данные и **emit-ят
намерения** (`attack_requested(attacker, target)`), а не дёргают `_send` напрямую. `Main`
— единственный, кто знает про сеть и склеивает всё.

## 2. Почему дальнейшее механическое дробление ждёт архзадачи

Оставшиеся builder-ы (`_board_row`/`_creature_card`, `_hand_row`, `_manarow_view`/
`_awaken_chip`/`_revealed_thumb`, `_aura_tile`, оверлеи Mulligan/Scry/GameOver) — **уже не
самостоятельные виджеты, а view-контроллеры, сросшиеся с координатором**: держат состояние
в `Main` (`_mull_sel`, `_scry_sel`, узлы) и зовут его методы из closures
(`_attack_creature`/`_play_at_drop`/`_can_play_here`/`_rebuild`/`_make_card`/`_ability_*`).
Чтобы вынести — нужна host-инъекция и вызовы `host._method(...)`, которые **парсер не
проверяет** (только живой тест), при малом выигрыше и реальном риске.

**Решение: дальнейшее дробление НЕ делаем механически.** Настоящий следующий шаг —
архитектурный: **инкрементальный апдейт всего борда вместо полного `_rebuild`** (раздел 3).
Тогда у виджетов появится явная модель узлов и сигнальная шина, и разнос станет
естественным и безопасным.

## 3. Инкрементальный апдейт борда

**Сделано (фундамент, P1–P4).** Существа и рука — **постоянные узлы с ключом = id** в слоях
ручной раскладки (`BoardLayer`/`HandRow`), реконсилируемые на каждый view; позиции
**твинятся** (плавный рефлоу соседей, въезд карты рука→стол `Fx.fly_in`, смерть проигрывается
в слоте). Узлы переиспользуются: данные хранятся в `node.set_meta("cr")` /
`set_meta("hand_index")`, замыкания читают мету (не захватывают устаревший `cr`); контент
лица перерисовывается на том же внешнем узле (`_creature_card` = make, `_refresh_creature` =
update). Мана-блок и стопки — пульс-дифф (`_animate_piles`) без персистентных узлов.

**Остаток (= Фаза D плана рефакторинга).** Главный `_rebuild` всё ещё **полностью
пересобирает не-бордовую часть** (медальоны героев, колонки стопок, баннер). Дальше:

1. **Распространить узловую модель** на эти стабильные узлы — обновлять по месту, не
   пересоздавая.
2. **Ввести явную сигнальную шину намерений** (attack/play/place_mana/awaken) вместо
   closures, дёргающих методы `Main` — это снимет host-инъекцию из раздела 2.
3. После 1–2 — **безопасно вынести** оставшиеся builder-ы (`BoardRow`/`HandRow`/
   `PilesColumn`/`ManaRow`/оверлеи) в свои модули с тестами; `Main` ужать до координатора
   (~250 строк, цель из раздела 1).

**Модель узла (паттерн, держать при расширении).** Замыкания узла (`can_drop_fn`/`drop_fn`/
`payload`) НЕ должны захватывать данные напрямую — иначе при переиспользовании узла они
устаревают. Текущее состояние кладём в `node.set_meta(...)`, замыкания читают `get_meta(...)`.
Обновление узла = обновить мету + перерисовать гемы/статусы/modulate/ability-dock, сохраняя
внешний узел (дёшево при ≤8 картах, выигрыш — стабильный identity для твинов).

## 4. Стретч (после раздела 3)

- **Типизированная модель** (`Card`/`Creature`-обёртки вместо голых `Dictionary`) — убирает
  primitive-obsession (карты/существа/payload-ы драга сейчас stringly-typed словари).
- **Таблица дизайн-токенов** (палитра/типошкала/радиусы/тени) вместо разбросанных
  `Color(...)`-литералов и размеров.
